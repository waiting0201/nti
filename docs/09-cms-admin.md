## 1. 三條專案決議（本文件的裁切依據）

1. **後台以單元功能為主** — 一個前台內容區塊 = 一個後台單元，各自獨立的清單／編輯畫面。不做通用 page-builder、不做區塊拖拉組版。
2. **不做 Media Library** — 沒有「媒體管理」選單。圖片／檔案只能從**所屬欄位**上傳，隨該筆資料建立與刪除；**每個上傳欄位旁必須顯示建議尺寸提示**（§3 為權威文字）。
3. **固定文字區不做後台** — 品牌敘述型的長篇文案寫死在前端（清單見 §7），後台只保留這些頁的 SEO 欄位。

## 3. 上傳欄位與建議尺寸（**權威文字，逐字顯示在欄位旁**）

| 單元 | 欄位 | 欄位旁提示文字 |
|------|------|---------------|
| `home-banner` | 桌機圖 | 建議 **2400×900px**（16:6）｜JPG／WebP｜≤500KB |
| `home-banner` | 手機圖（選填） | 建議 **1080×1350px**（4:5）｜JPG／WebP｜≤300KB｜未上傳則沿用桌機圖 |

| `solution` | 品項圖 | 建議 **1280×960px**（4:3）｜JPG／WebP｜≤300KB |
| `project` | 案例圖 | 建議 **1160×940px**（約 5:4）｜JPG／WebP｜≤300KB |
| `news` | 封面圖 | 建議 **1800×1200px**（3:2）｜JPG／WebP｜≤400KB |
| `news` | 內文插圖（編輯器內） | 建議寬度 **1800px**（3:2 最佳）｜JPG／WebP｜≤400KB |
| `certification` | 認證 Logo | 建議 **600×600px 去背 PNG 或 SVG**｜主體置中滿版、四周留白請先裁掉｜≤100KB |
| `client` | 客戶 Logo | 建議 **短邊 ≥300px 去背 PNG 或 SVG**｜≤100KB |
| `facility` | 設備照 | 建議 **1200×1200px**（1:1）｜JPG／WebP｜≤300KB |
| `vlog` | 縮圖覆蓋（選填） | 建議 **1280×720px**（16:9）｜未上傳將自動取 YouTube 官方縮圖 |
| `page`／`news`／`solution` | OG 分享圖（選填） | 建議 **1200×630px**（1.91:1）｜JPG／PNG｜≤300KB｜未上傳則沿用封面圖｜**僅此三個單元有此欄位**（§5.6；對應 `Page`／`News`／`Solution` 的 `OgImagePath`） |
| `supplier-notice` | 公告附件（選填） | PDF｜≤20MB |
| `supplier-download` | 下載檔 | PDF／XLSX／DOCX／ZIP｜≤20MB｜檔案類型與大小由系統自動帶入前台 |
| （前台）`get-a-quote` | 設計稿上傳 | PDF／AI／PSD／JPG／PNG／ZIP｜單檔 ≤20MB｜最多 5 個檔案 |

**共通規則**
- 每個圖片上傳欄位**必附一個多語 `Alt` 文字欄位**（中／英各一，必填）— 05-seo 硬性要求。
  適用範圍是**頁面上呈現的 `<img>`**。三個例外在欄位宣告處以 `altExempt` 寫明理由，不是靜默豁免：
  客戶 logo（以品牌名稱作為 alt，單元 09 明訂）、OG 分享圖（`og:image` 是 meta 標籤，
  頁面上沒有這張圖）、vlog 縮圖覆蓋（緊鄰影片標題的裝飾性圖片，前台以 `alt=""` 呈現，
  補 Alt 會讓螢幕閱讀器把標題唸兩遍）。
- 上傳後由後端驗副檔名白名單 + 檔頭 magic number，另存 WebP 衍生檔供前台使用（原檔保留）。
- 超過建議尺寸不擋，但後台顯示黃色提醒「圖片 3200×1200，超過建議尺寸，將由系統壓縮」。
- 尺寸不足一半時擋下並提示重新上傳（避免前台糊圖）。
- ⚠️ 認證 logo 現有素材僅約 152×165px（見 [IA §6](../reference/官網資訊架構_IA.md)），**上線前需向客戶索取向量原檔**。

| 頁面內容 | 富文本 | | ✓ | **僅 `HasRichBody = 1` 者顯示此欄位**：`privacy-legal`，以及預留的 `green-csr` |

### 16 `redirect` 301 轉址
來源路徑（唯一、小寫）／目標路徑／狀態碼（301／302／308）／啟用／命中次數（唯讀）。支援 **CSV 匯入匯出**（舊站 46 頁 + 80 篇文章的對照表）。儲存時檢查轉址鏈與迴圈並擋下。

### 17 `quote` 報價需求
**前台來源**：`get-a-quote.html`。**唯讀資料 + 可改狀態**，不可編輯客戶填寫內容。

- **清單**：報價單號、公司、聯絡人、產品類型、狀態、送出時間；可依狀態／日期區間／關鍵字篩選。
- **詳細**：完整表單內容（公司／聯絡人／Email／電話／產品類型／產業／數量／尺寸／材質偏好／期望日期／永續建議勾選／需求描述）＋ 設計稿附件下載。

  > **附件不做病毒掃描**（2026-09-08 決策）。原規格是「掃毒未通過者不提供下載」，但本期不接掃描服務——
  > 接 Defender for Storage 是每月固定成本（Standard Node ≈ US$10／storage account，另計 $0.15/GB），
  > 與這個案子的規模不成比例。閘留著而沒有東西會把狀態改成 `Clean`，結果是後台永遠下載不到任何附件。
  > 改以三件事壓風險：下載限超管（`quote.download`）、後端一律以 `application/octet-stream` + `nosniff`
  > 送出（不讓瀏覽器直接開啟 PDF／SVG），後台介面明示「未經掃描，請存檔後用防毒軟體確認再開」。
  > 日後要接掃描服務，需重新加回 `QuoteAttachment.ScanStatus` 欄位與回寫事件入口。
- **可改**：狀態（待處理／處理中／已報價／已結案／垃圾訊息）、承辦人、內部備註、標記已回覆。
- **匯出**：依篩選結果匯出 CSV（權限 `quote.export`，匯出行為寫入 `audit`）。
- **通知**：送出時寄業務通知信 + 客戶確認信，寄送結果記於 `EmailLog`，後台可查看失敗原因並重寄。

### 23 `admin` 管理員與角色
管理員：帳號／通知信箱／顯示名稱／角色／啟用／最後登入；**密碼由建立者直接設定**。**登入失敗不鎖定帳號**（客戶 2026-09-09 決定移除：持續用錯誤密碼打某個帳號就能把真正的管理員鎖在外面，而攻擊者不必知道任何密碼）；暴力破解由登入端點的 reCAPTCHA v3 擋。
**帳號（`Username`）不限定 email 格式**、建立後唯讀（改帳號等於換一個人，稽核紀錄會對不上）；
**密碼在新增視窗直接輸入（至少 6 碼、需輸入兩次），系統不寄啟用信、也不產生亂數密碼**（客戶 2026-09-09 決定）；
帳密由建立者當場轉交，建立出來的帳號不強制首登改密碼。忘記密碼時在編輯視窗重設一組新的
（`PUT /admin/admin/{id}/password`，權限 `admin.edit`），同樣不寄信。通知信箱純粹是系統通知用，與登入無關。
角色：三個系統角色（超級管理員／內容編輯／檢視者，不可刪）＋ 權限矩陣勾選（§6）。
**不可停用或降級自己**；系統至少保留一名啟用中的超級管理員。
刪除管理員是**真的刪除**（不是軟刪），刪掉後同一個帳號名可以重新建立；此人建立／修改過的內容不受影響，只是 `CreatedBy` 不再對得回一個帳號。

### 24 `audit` 信件紀錄
唯讀。列出 `EmailLog`：時間／收件者／主旨／狀態／失敗原因，失敗者可重寄（`audit.resend`）。可依狀態篩選。

## 5. 共用 UI 與行為規則

### 5.1 清單頁
分頁（預設 20 筆）、關鍵字搜尋、狀態篩選、**中/英完成度 badge**、批次上／下架、批次刪除（軟刪）。有 `SortOrder` 的單元提供拖曳排序，排序結果即時儲存。

### 5.2 編輯頁
左側為語系中性欄位（圖片、日期、分類、狀態），右側為 **中文／English 分頁**的文字欄位。切換語系不離開頁面、不遺失未存內容。離開前有未儲存變更時攔截。

### 5.3 多語
- 儲存時允許只填一種語系（存草稿），但**上架時必須兩語系皆完整**，否則擋下並指出缺漏欄位。
- 「複製中文到英文」按鈕，供先上架後翻譯的情境。

### 5.4 上下架
`上架` 開關 + `上架時間` + `下架時間`。三者組合的顯示狀態：草稿／已排程／上架中／已下架。時間以台北時間輸入、存 UTC。內容變更後由 webhook 觸發前台 ISR revalidate（05-seo §2.4）。

### 5.5 富文本編輯器
白名單標籤：`p h3 h4 strong em ul ol li a blockquote img figure figcaption br`。
禁止：`script iframe style` 與行內 `style`（YouTube 影片一律走 `vlog` 單元的欄位，不從編輯器貼 iframe）。
貼上 Word／網頁內容時自動清除樣式。伺服器端二次 sanitize，不信任前端。

### 5.6 SEO 欄位組（`page`／`news`／`solution`）
Slug、SEO Title（70 字提示）、Meta Description（180 字提示）、Canonical、OG 標題／描述／圖片。
Slug 由標題自動產生、可手改；重複時擋下。已上架內容改 slug 時，**自動在 `redirect` 建立一筆 301**。

### 5.7 刪除
內容一律**軟刪**（`IsDeleted = 1`），列表隱藏；分類以停用取代刪除。
**管理員（單元 23）是唯一的真刪**——軟刪會讓那個帳號名再也無法重新建立（2026-09-09）。刪除前確認對話框需顯示前台影響（例如「此分類有 8 篇新聞引用」）。

### 5.8 驗證與安全
必填／長度／格式（Email、URL、YouTube ID）皆前後端雙重驗證；後端為準。後台 SPA 以 `X-Robots-Tag: noindex` 排除索引，所有 `/api/v1/admin/*` 需 JWT + RBAC 檢查。
